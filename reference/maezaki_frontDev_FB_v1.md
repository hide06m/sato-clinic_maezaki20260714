## 🟡 もっと良く（プロの納品物にするなら、ここ）

**1. 院長挨拶のカードが縦に長すぎて、1画面に収まらない。**
実測すると、院長挨拶カードの高さは **幅1440pxで872px、幅1024pxで749px**。ノートPCの表示領域（約720〜800px）を**超えていて、1画面に入りきりません**。原因は写真部分に `min-height: 730px` の高さ固定がかかっているためです（`css/style.css:1124`）。3カラム（縦書き"MESSAGE"／写真／本文）のうち写真が主役級に大きく、挨拶文より写真の存在感が勝っています。
→ **方向**：写真の高さ固定を外す（または縮小して本文と背丈をそろえる）、縦書きラベルを削って2カラムにする、のいずれか。「一画面に挨拶が収まる」を目標にすると、ぐっと読みやすくなります。

**2. 本文フォントが14〜15px。高齢の患者さんには少し小さい。**
実測で、診療内容の本文＝14px、FAQの回答＝14px、当院についての本文＝15px（`css/style.css:1157` ほか）。依頼書5章のデザイン要件に「**高齢の患者様も読みやすいフォントサイズに配慮**」と明記があります。14pxは今どきのデザインとしては普通ですが、**この客層（来院者の2〜3割が65歳以上）**を思うと、読ませる本文は **16px以上**が安心です。
→ **方向**：装飾ラベル（11〜12px）はそのままでよいので、「段落として読ませる文章」だけ16pxへ。

**3. トップの画像が合計11.8MB。低速のスマホだと開くのが重い。**
トップページが読み込む画像は**26枚で合計11.8MB**でした（実測）。内訳の重いものは、スタッフ切り抜きPNG 4枚が各1.1〜1.3MB、当院ギャラリーのJPGが最大1.1MB。いずれも**支給状態のまま（無圧縮・PNG/JPGのフル解像度）**です。ご指摘のとおり、電波の弱い場所のスマホでは表示が待たされます。
→ **方向**：表示に必要な大きさまで長辺をリサイズ → JPG圧縮 or WebP化で、**1枚あたり100〜200KB**を目標に。特に切り抜きPNG（透過が要らない写真部分）はJPG/WebPに変えるだけで数分の1になります。トップ全体を2〜3MBに収められれば体感が変わります。

**4. トップの本文が「JSが動く前提」で隠れている。JSが失敗すると本文が消える。**
トップの各セクション（診療時間・お知らせ／院長挨拶／診療内容／当院について／アクセス）は、スクロールで浮き上がる演出のため**初期状態が透明（opacity:0）**で、JavaScriptのスクロール検知が動いて初めて表示されます（実測：スクロール前は5セクションとも `opacity:0`・`css/style.css` の `.reveal` ＋ `js/main.js:290`）。つまり**JSが読み込めない／エラーで止まると、トップは上部だけ表示され、お知らせや地図など（MUSTの中身）が空白のまま**になります。上の③の重い画像と重なると、低速回線で現実に起きえます。
→ **方向**：初期表示は「見える」状態にしておき、アニメは**あくまで飾りとして後から足す**（プログレッシブ・エンハンスメント）。`.reveal` を最初から `opacity:1` にし、JS側で「動かせる時だけ」フェードを付ける形にすると、JSが死んでも本文は必ず出ます。

**5. 掲載原稿との差分が数点。原稿は「改変不可・追加は要連絡」が原則。**
高精度な中で、次の差分がありました（原稿と照合）。
- **「医院の理念・方針」の導入文が、サイトのどこにも無い**（原稿"佐藤医院は、地域医療の一翼を担う医療機関として…"／全HTMLをgrepしてもヒット0）。7項目のリストは載っていますが、その前置き文だけ落ちています。
- **「当院について」の導入文が about ページの本文に無い**（原稿"…より良い生活をサポートすることを使命としています…"）。トップには載っていますが、当院についてページ単体で読むと、そのページの導入が抜けて見えます。
- **ヒーローの「内科・心臓・呼吸器・消化器」**（`index.html:70`）。原稿の診療科目は「内科／**循環器科**／呼吸器科／…」で、"心臓"は言い換え、"消化器"は診療科目一覧にない語です。
- **お知らせ①に原稿に無い一文が追加**されています（"接種時期や対象年齢などの詳細は…"／`js/news-data.js:10`）。
→ **方向**：抜けている導入文は戻す。言い換え・追加は、原稿どおりに戻すか、変えたいなら「院長に一言確認」。実務では**勝手な言い換え・加筆がいちばん揉める**ので、"直す"より前に"確認する"癖を。

**6. 使っていない重い画像が5.6MB分（17枚）、リポジトリに残っている。**
`hero-circle-option-b.png`（1.48MB）・`hero-circle-selected.png`（1.39MB）など、**どのHTML/CSS/JSからも呼ばれていない画像**が17枚（計5.6MB）残っています（制作途中のボツ案と思われます）。`news_logo.textClipping`（0バイト・macOSの操作痕）も混ざっています。
→ **方向**：納品前に「使っている画像だけ」に整理。動作には影響しませんが、リポジトリが軽くなり、次に触る人が迷いません。

**7. ヒーローのカードが「リンクだ」と気づかれにくい。**
ヒーローの4枚のカード（初めての方へ／診療時間／症状から探す／アクセス）は、ふわふわ浮いてドラッグでき、カーソルも掴む手（grab）が既定です（実測：カード=grab／リンク部分だけ pointer・`css/style.css:422,490`）。ドラッグ演出は目を引きますが、**「押せる」「別ページへ飛ぶ」という手がかりは、小さな矢印とホバー時のわずかな影の変化だけ**。ご指摘のとおり、リンクだと気づかず素通りされる可能性があります。カードは患者さんが主要ページへ最短で行くための入口なので、ここは**"目を引く"より"押せると分かる"を優先**したい所です。
→ **方向**：ホバーで色/枠がはっきり変わる・カード全体が持ち上がる等、「これは押せる」と一目で分かる反応を強める。ドラッグ演出はサブに。

## 💭 考えてみよう（正解のない、プロの判断どころ）

**1. スタッフ写真が「目元で切れている」演出は、この医院に合っている？**
スタッフ紹介の切り抜き写真（トップのボタン・当院についてのカード）は、顔が額〜目のあたりでトリミングされています。おしゃれで動きは出ますが、**医療・手術を連想させる医院で、"目が見えない人物"は不安を与えないか？** エンタメサイトなら攻めの演出として良いけれど、患者さんが「この人に診てもらう」と安心したい医院では、**顔がちゃんと見える**方が信頼につながるかもしれません。——正解はありません。「このサイトの目的（安心・信頼を与える）に、この演出は効いているか？」を、自分の言葉で説明できるか考えてみてください。それが言えれば、演出は"狙って"やっていることになります。

**2. このサイトは「動き」が多い。この客層に、その量は合っている？**
浮遊するカード・自動で流れるギャラリー・1秒ごとに更新される受付カウントダウン・スクロールで現れる演出——動きが豊かで今風です。一方で、来院者の2〜3割が高齢者・こういう演出は乗り物酔い（vestibular）に弱い人もいます。今回、**「動きを減らして」という利用者設定（prefers-reduced-motion）への対応が0件**でした。
→ ヒント：CSSに `@media (prefers-reduced-motion: reduce) { … }` を足して、その中で動きを止める／控えめにする、という作法があります。「動きが好きな人には見せ、苦手な人には静かにする」を両立できます。**誰に向けたサイトかで、動きの"量"を決める**——その視点を持てると一段上です。
